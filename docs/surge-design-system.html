Surge

A menu bar instrument for coding agents. It shows every orchestrator and worker you have running: how full each context window is, how fast tokens are flowing, what it's costing, and which agent has stopped moving.

This document turns the AgentPulse wireframe and the macOS blueprint into one system for three surfaces: the menu bar extra, the popover dashboard (which can be detached as a floating panel), and desktop widgets. Every rule cites the Apple Human Interface Guidelines page it comes from. Anything without a citation is a design judgment and is labeled as one.

Thesis

Quiet when everything is fine, loud only when an agent needs you.

People run Surge so they don't have to watch terminals. Most of the time the right answer to "is anything wrong?" is no, and the interface should say that calmly, in grey. Color, motion, and notifications are held back for the moments that need a decision: an agent that has stalled, an agent waiting for permission, a context window about to compact, a wallet running dry. Because the rest of the interface is grey, red and orange always mean something.

Principle 1

Status owns color

Red means "needs you now." Orange means "needs you soon." Nothing else uses those hues: not providers, not charts, not branding. Controls use the system accent color you picked on your Mac.

Principle 2

One meter, everywhere

The Fuse, the context meter, looks the same in the menu bar, the popover, the panel, and widgets, so it only has to be learned once (charting-data.md › Designing effective charts).

Principle 3

Meaning survives grayscale

Desktop widgets on the Mac turn monochrome in vibrant mode. Every state has a shape, a symbol, and a word as well as a color (widgets.md › Using color).

Principle 4

Glance, then one click

Every alert sits next to the thing it's about and comes with the single action that resolves it. Deeper analysis lives in the popover, not in widgets (feedback.md, widgets.md › Adding interactivity).

Signature

The Fuse. Every agent's context window is drawn as a capsule with two notches cut at 70% and 90%. When an agent stalls, the fill freezes and turns into a red hatch: a tripped fuse. The idea comes from the product's name: tokens are current, the context window is capacity, a stalled agent is a tripped breaker. Everything around the Fuse stays quiet so it carries the identity on its own (design judgment, consistent with branding.md › Best practices: "Ensure branding always defers to content").

What this direction rejects, and why

The wireframe's look (near-black canvas, grid background, ambient glow, one emerald accent) is one of the most common defaults in generated developer tools. Nothing about it comes from this product. A second draft of this system used a violet "ion" brand color for throughput. I dropped it because violet has become the stock "AI product" color and because it would compete with status. The result is a graphite instrument with system materials, where the only color appears when something goes wrong.

Wireframe review

An audit of surge-wireframe.html (AgentPulse × herdr). I read it from the source because it loads Tailwind and its fonts from a CDN, so contrast figures are computed from its hex values.

Summary — Critical issues

The wireframe has the right data model: an orchestrator→worker hierarchy, context pressure, stall detection, and spend. It also has two good instincts worth keeping: a hatch pattern for stalled agents and tabular numerals. But it's framed as an iOS home-screen widget when the product is a macOS menu bar app. Its 9 px text is below the macOS minimum. Status depends on color in places where macOS desktop widgets remove color. And it packs a three-tab app into a widget. As it stands, it would be remembered for its look, not for anything specific to Surge.

Critical

CriticalText is set at 9–10 px throughout the widget

Why: typography.md › Ensuring legibility: the macOS minimum is 10 pt. widgets.md › Displaying text in widgets: "In general, display text using fonts at 11 points or larger."

Fix: Widget text is 11 pt minimum. In the popover, 11 pt (Subheadline) for metadata, 10 pt only for chart axis ticks. See Type.

CriticalSecondary labels fail contrast: zinc-500 #71717A on card #16181D is 3.67:1

Why: accessibility.md › Vision: text up to 17 pt needs 4.5:1. zinc-600 #52525B (used in a few places) is 2.30:1.

Fix: Secondary text is #6E6E73 on light (5.07:1 on raised) and #A1A1A6 on dark (4.90:1 on raised). In production, use .secondary.

CriticalProviders and states are told apart by hue alone

Model dots, colored progress fills, and concurrency bars encode meaning only in color. On Mac, desktop widgets render in the vibrant mode, which "desaturates text, images, and gauges", so the provider colors collapse to the same grey.

Why: accessibility.md › Vision: "Convey information with more than color alone." widgets.md › Rendering modes (Mac: vibrant on Desktop).

Fix: Providers get a text label. Status gets an SF Symbol plus a word plus a shape change in the Fuse. Charts use direct labels and separators (charts.md › Color).

CriticalInfinite pulsing, ping, and border-flash animations

The radarPulse, animate-ping, and stuckBorderPulse animations loop forever, and none of them responds to Reduce Motion.

Why: accessibility.md › Cognitive: "Be cautious with fast-moving and blinking animations." motion.md: "generally avoid adding motion to UI interactions that occur frequently."

Fix: No looping animation anywhere. A single 0.3 s transition when state changes. See Motion.

Improvements

HighWrong platform frame

It shows a 9:41 status bar, "iOS 18 WidgetKit", and iPhone widget sizes. The blueprint targets a non-sandboxed macOS app with MenuBarExtra and desktop widgets, and the menu bar surface isn't drawn at all.

Fix: Design for the menu bar extra, the popover and detached panel, and Mac desktop widgets. Watch the 24 pt menu bar height (the-menu-bar.md › Menu bar extras).

HighThe widget is a small app: three tabs, expandable chips, scrolling lists

Why: widgets.md › Adding interactivity: "avoid creating app-like layouts in your widgets" and "reserve complexity for your app."

Fix: Ship two widget kinds, Agents and Spend. Each has one job, uses no tabs, and has at most one button (Nudge Agent, shown only when something has stalled). The tabs move into the popover.

HighAssumes per-second updates

The wireframe ticks uptime every second. Widgets "don't support continuous, real-time updates."

Fix: Show uptime and stall time with Text(date, style: .timer) so the system keeps them current (widgets.md › Updating widget content). Reload the timeline when an agent stalls or recovers, and show "Updated 2 min ago" when data is stale.

HighColor means several things at once

Green means OpenAI and also "healthy/optimal." Cyan means DeepSeek and also "current concurrency bar." Amber means "high context" and also half of the stalled hatch.

Why: color.md › Best practices: "Avoid using the same color to mean different things."

Fix: Red and orange are reserved for status. There is no green state: healthy is the default and gets no color.

HighDark only, with a hand-drawn blur on the widget body

Why: dark-mode.md: "Ensure that your app looks good in both appearance modes." liquid-glass.md › The two layers: glass belongs only to the functional layer, and the widget body is content.

Fix: Use system backgrounds (containerBackground) for widgets and system popover glass for the popover. Content cards are opaque fills. Light and dark tokens are defined below.

MediumJargon and mixed capitalization

"herdr", "Swarm", "Long-horizon mission", "DAG milestones", "lanes", "COMPACT SOON", "OPTIMAL", all-caps mono eyebrows, plus title case and sentence case mixed together.

Why: writing.md › Best practices: "Adopt capitalization rules that align with your app's style, then apply them consistently," and "Prioritize clarity and avoid the temptation to be too cute or clever with your labels."

Fix: Use the vocabulary in Writing: Orchestrator, Worker, Working, Waiting for you, Stalled.

MediumMonospace is used as the default label face

Why: typography.md: "Minimize the number of typefaces you use." In the wireframe, mono is doing the job of hierarchy.

Fix: SF Pro everywhere, with .monospacedDigit() for numbers. SF Mono only for things you would type in a terminal: paths, session IDs, model IDs.

What works — keep it

  • A hatched fill for a stalled agent. A pattern survives grayscale, and it becomes the Fuse's tripped state.
  • Tabular numerals on every changing value.
  • The Nudge action sits on the stalled row itself, not in an alert (feedback.md: "Consider integrating status feedback into your interface").
  • Context thresholds come with words, not just colors ("HIGH CTX"). Keep the idea, change the words.
  • The stacked cost bar has 2 px gaps between segments (charts.md › Color: "adding visual separation between contiguous areas of color").

Color

Eleven tokens: three surfaces, three text levels, one meter, two status signals (each as a fill and an ink), and the system accent. Surfaces and text map to system semantic colors. Only the status signals are custom asset-catalog Color Sets, because system orange and red on light backgrounds can't pass contrast as text (orange is 2.03:1 on #F6F6F6).

Rules

  • A text label always accompanies the Fuse: a percentage, plus a word at the thresholds (gauges.md › Best practices: "Write succinct labels that describe the current value").
  • Tripped is a pattern, not just a color, so it survives vibrant and grayscale rendering.
  • The axis is fixed at 0–100% of the model's window. Never rescale (charts.md › Axes: fixed range "when specific minimum and maximum values are meaningful").
  • The fill animates only when its value changes (≤ 0.3 s ease-out). It never pulses.
  • VoiceOver: "Context 72 percent of 200 thousand tokens, high."
  • SwiftUI: a custom GaugeStyle, so it stays a real Gauge for accessibility.

Attention banner

  • Appears at the top of the Agents tab only for Stalled and Waiting for you, sorted alert first. At most 3 are shown; the rest collapse into "2 more need you".
  • Each banner has one action, labeled with a verb (writing.md › Best practices: "Be action oriented"). Stalled → Nudge Agent. Waiting → Show in Terminal.
  • It disappears when the condition clears, with no "dismiss" step. It's feedback in place, not an alert (feedback.md › Best practices).
  • Background is a 10–16% status tint, text is text.primary, and the symbol is the status fill.

Menu bar extra

The menu bar is the product's resting state: one template glyph of up to four vertical mini-Fuses (the busiest agents), with an optional short readout. It's 22 pt tall inside the 24 pt menu bar (the-menu-bar.md › Menu bar extras).

Glyph rules

  • A template image (black and clear) so the system can recolor it for light and dark menu bars and the selected state (the-menu-bar.md › Menu bar extras). Exported as a custom SF Symbol with variable layers.
  • Bar height = context fill. A stalled agent's bar is drawn hollow with a dot, so the alarm is a shape change and stays readable in monochrome.
  • When anything needs you, an exclamation mark and a count are appended. That's the only change.
  • Optional color: Settings › "Tint menu bar icon when an agent needs you" (off by default) tints only the exclamation mark. Design judgment: the template rule wins by default.
  • Readout options (Settings): None · Agents · Spend. Never more than one number. The blueprint's "1 Orch · 2 Workers · $1.42" is too wide for a crowded menu bar, which the system will hide.
  • No animation in the menu bar, ever.

Click behavior

  • Click opens the popover (MenuBarExtra, .menuBarExtraStyle(.window)). HIG prefers a menu "unless the app functionality you want to expose is too complex for a menu." Surge's charts and live tree qualify.
  • Secondary-click opens a plain menu: Open Surge Panel, Pause Monitoring, Settings…, Quit Surge. This gives keyboard and VoiceOver users the core commands without the dashboard.
  • People choose whether the item appears. It's an onboarding toggle and a General setting (the-menu-bar.md: "Let people — not your app — decide").
  • Because the system can hide extras, everything is also reachable through a Dock menu (when the Dock icon is shown), the panel, and a global shortcut people set themselves (the-menu-bar.md: "Avoid relying on the presence of menu bar extras").
  • Accessibility label: "Surge. 5 agents, 2 need you. 16 dollars 91 spent today."

Popover & panel

The dashboard. It's 360 pt wide, grows to 600 pt tall, and then scrolls. It has three tabs in a system segmented control, ordered by how often people need them. Drag it away from the menu bar to detach it as a floating panel, which is the "standalone on the desktop" mode (popovers.md › Desktop (macOS): "Consider letting people detach a popover").

Rules

  • The header status always gives the count of agents that need you, as a word plus a symbol. When all is well it says "All agents working" in secondary.
  • Workspaces are sorted by most urgent state, then by spend. Groups with nothing needing attention can collapse, and the collapsed state is remembered.
  • The footer holds non-critical context, so placing it at the bottom is fine. Critical states never live only in the footer: a low wallet also appears in the Spend tab and as an Active notification.
  • Pin (macwindow.on.rectangle) detaches the popover. The detached panel looks the same plus a title bar: "Surge" (popovers.md: "Make minimal appearance changes to a detached popover").
  • More (⋯) is a pull-down menu: Pause Monitoring, Reset Today's Counters…, Settings… (⌘,), Quit Surge (⌘Q).
  • Settings live in a standard settings window, not inside the popover (settings.md).
  • Empty state: "No agents running" plus a hint: "Start Claude Code, or point workers at 127.0.0.1:8899." Setup and help, never blank (writing.md › Best practices).

Motion

One choreographed moment. Everything else is the system's default.

Trip and reset

When an agent stalls, its Fuse fill stops, and the hatch fades in over 0.3 s. It happens once. When the agent recovers, after a Nudge or on its own, the hatch clears from left to right and the fill resumes, a 0.4 s spring. That's the only time Surge moves on its own initiative, and it marks the only event worth noticing.

With Reduce Motion on, states swap instantly with a cross-fade.

// Agent state → presentation (one source of truth for every surface)
enum AgentStatus { case working, waitingForYou, stalled(since: Date), compacting, idle(since: Date), done, noSignal }

extension AgentStatus {
    var symbol: String {
        switch self {
        case .working:       "bolt.fill"
        case .waitingForYou: "hand.raised.fill"
        case .stalled:       "exclamationmark.triangle.fill"
        case .compacting:    "arrow.down.and.line.horizontal.and.arrow.up"
        case .idle:          "pause.fill"
        case .done:          "checkmark"
        case .noSignal:      "bolt.slash"
        }
    }
    var needsYou: Bool { if case .stalled = self { true } else if case .waitingForYou = self { true } else { false } }
}

// The Fuse — a real Gauge with a custom style, so accessibility comes for free
struct FuseGaugeStyle: GaugeStyle {
    var tripped = false
    func makeBody(configuration: Configuration) -> some View {
        GeometryReader { geo in
            let v = configuration.value
            ZStack(alignment: .leading) {
                Capsule().fill(.quaternary)
                Capsule()
                    .fill(tripped ? AnyShapeStyle(HatchPattern(color: .surgeAlert)) // custom ShapeStyle: 45° stripes, 3 pt
                          : v >= 0.9 ? AnyShapeStyle(.surgeAlert)
                          : v >= 0.7 ? AnyShapeStyle(.surgeCaution)
                          : AnyShapeStyle(.surgeMeter))
                    .frame(width: geo.size.width * v)
                    .animation(.easeOut(duration: 0.3), value: v)
                ForEach([0.7, 0.9], id: \.self) { t in      // notches
                    Rectangle().fill(.background).frame(width: 1.5)
                        .offset(x: geo.size.width * t)
                }
            }
        }
        .frame(height: 6)
        .clipShape(Capsule())
    }
}

Platform target: the blueprint says macOS 14+. The visual language here assumes macOS 26+ system materials. On 14–15 the same tokens work, and the popover simply uses the older system material. Nothing in Surge depends on custom glass.

Open questions

  • What does "Nudge" do technically? Send a newline or "continue" to the agent's TTY, restart the worker process, or just open the terminal? The label should say exactly that. If it can lose work, it needs a confirmation (feedback.md: "Warn people when they initiate a task that can cause data loss").
  • Stall threshold. The wireframe uses 120 s. Reasoning models can think silently for longer. Make it per-model in models-pricing.json (for example, 300 s for deepseek-reasoner).
  • Budget. Is the daily budget a hard number people set, or derived from wallet balances? This decides whether "over budget" is caution or simply information.
  • App icon. Proposed: a graphite tile with three vertical Fuses, the middle one filled. It's the only place a brand color could appear, as a single warm filament in the filled Fuse. Needs its own exploration with light, dark, clear, and tinted variants.
